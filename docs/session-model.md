# IDE 会话模型

应用与项目的 Provider 所有权见 [架构说明](architecture.md)。

`ProjectWorkspace` 管理一个活动项目，串行处理打开、切换和关闭请求。
返回项目列表会保留活动项目；重新进入同一项目会复用它。切换到其他项目或点击
“关闭项目”时，先保存文档，再停止任务与语言服务，最后释放缓冲区。
保存失败会中止切换或关闭。

## 所有权

- `ProjectSession`：文档、项目 bash、执行记录、运行目标及语言服务生命周期。
- `ProjectDocuments`：每个打开文件的 `CodeController`、撤销、选区、脏状态和串行保存。
- `RunConfiguration`：执行什么命令、目标设备、任务类型及可选构建产物。
- `RunSession`：一次执行的唯一 ID、进程状态、退出码和控制台。
- `ConsoleSession`：PTY、输出、终端控制器、滚动位置、复制粘贴和停止释放。

运行目标与当前查看的控制台独立。切换查看构建日志不会改变运行目标；热重载与
热重启只发送给该目标对应的 Flutter/Web 运行会话。

## 执行和关闭

自动任务使用独立 PTY，不向用户 bash 输入命令。运行、构建、Git、新建、克隆、
环境安装和 ADB 操作均使用相同的控制台模型。短时文件操作仍走原生 `exec`。

同一配置的同时启动请求合并；重新运行先等待旧进程停止，再创建新的执行。
完成条件是真实退出码和输出流均已结束，不能靠日志关键词判断成功。
停止先发 Ctrl+C，超时后终止所属进程组。停止后的输出保留，关闭会话才释放。
释放终端控制器前先通知视图解绑。

环境安装属于应用，离开页面后继续；项目任务属于项目，返回列表后继续。
工作台 bash、项目 bash 和各任务的输入与输出相互独立。

当前会话状态仅保存在内存中，不跨应用进程重启恢复；文件通过自动保存和显式保存落盘。

## Web 预览

`ProjectSession.web` 管理 Web 服务、启动状态和 Flutter machine 协议请求。
每次运行分配新端口；只在当前执行报告 `app.webLaunchUrl` 和 `app.started` 后加载预览，
不会因端口可连接或 `main.dart.js` 返回 200 而认为应用已启动。Run 保持当前视图，不自动跳页。

手机使用项目内“代码 / 预览”切换，宽屏并排显示。切换与尺寸变化保留同一个 WebView，
返回键先回到代码。运行工具栏与终端共用；预览中的更新操作始终绑定 Web 执行。
保存成功后通过 `app.restart` 请求热重载或热重启，并等待对应结果；编译失败保留现有页面。
手动刷新是独立操作，会重置页面状态。

HTML 加载完成与 Flutter 首帧分开判断，首帧之前显示加载状态。主文档加载失败提供手动重试，
子资源错误不会触发整页刷新。退出编辑器返回项目列表后服务仍保留，但原生 WebView 随编辑器
销毁，重新进入会加载新页面；关闭项目会终止服务并清理待完成请求。

## 底部工作坞与输入

编辑器通过 `TerminalHost` 承载一个底部工作坞：常驻控制区包含视图切换、终端开关、
撤销/重做、键盘模式、目标和运行/构建操作；展开区在终端与代码键盘之间切换。
隐藏终端保留其视图、选区和输入状态，键盘避让与底部安全区只由宿主处理一次。
终端与代码键盘复用按键样式，终端扩展键靠近系统键盘，长按复制仍浮在输出区内。

代码键盘模式使用可编辑的 `TextField` 和 `TextInputType.none`，不使用 `readOnly`。
虚拟键在 `TextFieldTapRegion` 内保留编辑焦点，直接通过控制器与 `CodeInputFormatter`
完成编辑；无初始选区时在文末建立光标，继续使用同一套补全、保存和撤销流程。

## 工作台职责边界

- `EditorPage`：布局、文件树与 Git 入口、代码/预览切换、输入焦点与底部面板显示。
- `EditorSurface`：代码视图、补全浮层定位、诊断展示和编辑快捷键。
- `EditorIntelligence`：当前文档的同步、防抖、补全、签名与诊断；文档切换或失焦会使旧请求失效。
- `CodeController`：文本、选区、高亮和撤销历史；只有文本变化进入撤销历史，移动光标保留重做分支。
- `ProjectSession.language`：项目独有的语言服务客户端，负责协议顺序及进程事件归属；关闭项目时停止并释放订阅。
- `ProjectActions`：保存、目标校验、运行、构建、热重载及成功后的本机安装器调用；页面只触发命令和呈现结果。
- `EditorRunControls` / `TerminalSessionTabs`：运行目标和操作、终端会话的独立视图。

文档内容变化驱动自动保存；光标、选区和诊断变化不推迟保存。补全和光标位置只刷新编辑区，
文件脏状态只刷新标题；切换文件才重新绑定工作台的文档控件。

构建安装的结果写入所属任务日志，页面存在时另作提示；返回项目列表不丢失后续处理。
热重载在保存前绑定执行，保存期间若发生重新运行，则不会向新进程发送旧操作。
Web 预览中的目标标签与运行操作一致；选择 Android 目标会返回代码视图。

## 版本控制与 GitHub

编辑页侧栏提供“文件 / 版本控制”两个同级入口。文件树不再提供目录内克隆，
克隆项目统一使用项目列表入口。版本控制保留状态、两类差异、暂存/取消暂存、
提交暂存内容、还原未暂存改动、拉取/推送、基础分支、最近提交、远端和提交身份。

`ProjectSession.git` 管理 Git 操作和结果，侧栏关闭不影响执行；同一项目一次只运行一个
Git 操作。网络任务和 gh 登录使用项目控制台，状态查询使用短命令。状态使用 NUL 分隔，
原生 exec 保留原始字符，文件名和命令参数分别处理，支持 worktree 的 `.git` 文件。

拉取仅允许快进，切换分支/拉取前要求工作区干净；首次推送关联唯一远端。
还原需要确认且只还原未暂存内容，未跟踪文件删除仍交给文件树。
会修改工作区的操作先保存，再锁定编辑/保存，完成或中断后重新读入已打开文档；
变化的文档清除旧撤销历史，已删除的文档关闭，避免旧内容被自动保存回来。

GitHub 使用 gh 的非交互设备码流程，App 复制验证码并打开系统浏览器；
登录成功才执行 `auth setup-git`，退出后重新检查本地凭据。面板显示“已保存登录凭据”，
不把本地 token 存在视为远端校验成功。gh 缺失时提示安装，不在登录流程里自动安装软件包。
