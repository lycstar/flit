# Flit 界面术语与文案规范

界面参考 IntelliJ IDEA / Android Studio 的概念与常用称呼，按 Flit 的实际功能使用。产品与技术专名保留原文，例如 Git、ADB、SDK、NDK、Flutter、Dart、Web、APK。

## 统一术语

| 概念 | 统一称呼 | 使用说明 |
| --- | --- | --- |
| Project | 项目 | 使用“新建项目”“项目名称”“打开项目”“关闭项目”；不混用“工程”。 |
| Project tool window | 项目工具窗口 | 标签显示“项目”，用于浏览项目文件；首页称“项目列表”。 |
| Directory | 目录 | 操作为“新建目录”，与路径、主目录、输出目录一致。 |
| Code completion | 代码补全 | 候选称“补全项”；基础补全与语言服务提供的补全有明确区别。 |
| Syntax highlighting | 语法高亮 | 不称“本地高亮”，不暗示具备语义分析。 |
| Code analysis / Problems | 代码分析 / 问题 | 分析状态称“代码分析”，检查结果入口称“问题”，修复操作称“快速修复”。 |
| Soft wraps | 软换行 | 仅改变长行显示，不插入换行符。 |
| Editor color scheme | 配色方案 | 指编辑区域的代码配色，不等同于整个 IDE 的主题。 |
| Development environment | 开发环境 | 安装页包含基础环境、Android 工具链与 Flutter SDK。 |
| Run target | 运行目标 | Android 设备或 Web 预览；当前没有完整的运行配置编辑器，不使用相关功能名称。 |
| Build | 构建 | 使用“构建 APK（调试版）”“构建 APK（发布版）”“构建 Web（发布版）”；文件位置称“输出目录”。 |
| Version control | 版本控制 | Git 面板入口；工作目录中的改动称“本地更改”。 |
| Staging | 暂存 / 取消暂存 | 区分“已暂存”“未暂存”“未跟踪”；“提交更改”只提交暂存区内容。 |
| Commit | 提交 | 使用“提交消息”“提交历史”“提交者信息”。 |
| Rollback | 回滚更改 | 明确范围是未暂存的更改；不与撤销已提交历史、Git revert 混用。 |
| Remote | 远程仓库 | 分支跟踪关系称“上游分支”，仓库 URL 字段称“仓库地址”。 |
| Terminal | 终端 | 保留“终端会话”“终端输出”；清除显示使用“清空终端”，运行进程输出可称“运行日志”。 |
| Device pairing / authorization | 配对 / 授权 / 连接 | 配对记录不等于当前授权；配对端口与连接端口明确区分。 |
| GitHub device authorization | 设备授权码 | 与 Android 无线调试的“配对码”区分。 |

Flutter 的“热重载”“热重启”保留原名，不替换成 IDEA 的 HotSwap，也不将普通运行标为调试。

## 文案规则

- 操作名称使用动词与对象，例如“新建目录”“显示未暂存的差异”“配置开发环境”。
- 标签保持简短；说明文字解释操作条件或结果，不介绍实现细节。
- 使用中文标点和全角括号。命令、路径、URL、协议标记和外部工具原始输出保持原样。
- 状态统一为“检测中…”“就绪”“未安装”“安装中”“失败”“已停止”等，避免“预热”“起不来”“干净”等口语。
- 错误提示说明失败对象及下一步，不将校验失败、缺少组件、权限或依赖错误一律归因于网络。
- 删除、回滚等不可撤销操作说明具体影响范围，避免把关闭项目描述成删除。
- 界面与 Flutter 内置菜单统一使用简体中文；新增多语言支持时应同时覆盖自定义文案和内置控件。
